开放数据

本站页面上的插件目录与中文引用样式一览,也以 JSON 文件公开,方便你用程序读取、做统计或接入自己的工具。本页逐字段说明格式、更新方式和兼容承诺。

1. 公开的文件

地址内容什么时候更新
/data/catalog.json插件目录:插件广场上全部在架插件的名称、分类、适配范围、星标、下载与各 Zotero 大版本的安装包地址。随站点构建生成。站点通常每天自动刷新一次数据并重新构建(北京时间凌晨),代码更新时也会重新构建;以文件里的 generatedAt 为准。
/data/styles.json中文引用样式一览:样式 ID、标题、适用场景、引文方式、来源与许可等元数据,不含样式文件本身。与引用样式页上的表格是同一份数据。维护者手动运行核对脚本时更新,以文件里的 checkedAt 为准(目前是 2026-11-17)。
  • 两份文件都是 UTF-8 编码的 JSON,内容随站点一起公开发布,不需要登录或密钥。
  • 站点地图 /sitemap.xml 与站点说明 /llms.txt 也可以被程序读取,但它们只列页面地址,不是数据文件,格式不做下面的承诺。
  • 期刊查询不属于开放数据。它的接口只为本站页面服务:每次最多返回 20 条,有访问频率限制,不提供批量下载,请勿用程序批量抓取,见收录规则第 7 条。

2. 插件目录 /data/catalog.json

只包含在架插件;按收录规则下架的插件不会出现,作者发布新版本重新上架后会自动回到这份文件里。生成时会先校验格式,并核对条数与站点上的插件详情页数一致,不一致就不发布。

顶层字段
字段类型含义可否为空来源
schema整数格式版本号,目前是 1。不会缺省固定值
generatedAt日期 YYYY-MM-DD生成这份文件的构建日期(UTC)。不会缺省构建流程
site字符串本站地址,固定为 https://zoterocn.org。不会缺省固定值
count整数plugins 的条数,即在架插件数。不会缺省构建流程
categories数组本站分类:每项是 { key, label },key 是分类键(如 reading),label 是中文名(如「阅读」)。不会缺省本站分类
plugins数组在架插件,按 GitHub 星标从多到少排列,同分按名称。下架的插件不会出现。不会缺省见下表
plugins 数组里每一项
字段类型含义可否为空来源
id字符串插件的唯一标识,即代码仓库的「所有者/仓库名」,全部小写。不会缺省收录数据
name字符串插件名称(已去掉控制字符,限制长度)。不会缺省收录数据
summary字符串一句话用途简介。可能是空字符串收录数据(初始整理自 zotero-chinese/zotero-plugins)
category字符串主分类,取值是 categories 里的某个 key。不会缺省本站分类
author字符串作者名称。不会缺省收录数据
homepage字符串(https 地址)项目主页。不会缺省收录数据
stars整数GitHub 星标数,只代表热度,不代表质量。不会缺省GitHub 公开数据(每日刷新)
updated日期 YYYY-MM-DD本站记录到的最近一次发布日期。没有发布记录时整个字段省略GitHub 公开数据(每日刷新)
cadence对象更新节奏:r12 是近 12 个月(按每月 30 天计)的正式发布次数,days12 是其中有发布的天数(同一天发布多次只算一天,可能省略),last 是最近一次正式发布日期。预发布与草稿不计。读不到发布记录时整个字段省略GitHub 公开数据(每日刷新)
dl对象安装包下载:total 是发布页上全部 .xpi 安装包的累计下载次数之和,at 是统计日期。没有下载数据时整个字段省略GitHub 公开数据(每日刷新)
dlWeek整数或 null近 7 天新增下载:最近一次统计与恰好 7 天前的统计之差。两次统计缺一,或累计数变小,就是 null,不推算。算不出时为 null由每日统计算出
archivedtrue代码仓库已在 GitHub 上归档时出现,值只会是 true。归档本身不是下架理由。仓库未归档时整个字段省略GitHub 公开数据(每日刷新)
zotero对象适配范围:declared 表示作者是否声明了适配的 Zotero 版本;majors 是声明范围覆盖的 Zotero 大版本(如 [7, 8, 9, 10])。未声明不等于不兼容。不会缺省作者发布信息
releases数组每个 Zotero 大版本(7 及以上)对应的最新安装包,按大版本从小到大。只收 github.com 上、属于该插件自己仓库的 .xpi 地址,其余地址不进这份文件。可能是空数组见下表
releases 数组里每一项
字段类型含义可否为空来源
t整数这个安装包面向的 Zotero 大版本(7 及以上)。同一插件内不重复。不会缺省作者发布信息
v字符串插件版本号。不会缺省作者发布信息
u字符串(https 地址)安装包直链,指向作者在 GitHub 上的发布页,本站不托管安装包。不会缺省作者发布页
i字符串安装包里声明的 Zotero 插件标识(如 xxx@example.com),可用来判断某个插件是否已安装。取不到时省略zotero-chinese/zotero-plugins 的公开目录,没有的读取自安装包本身
min字符串作者声明的最低 Zotero 版本。作者未声明时省略作者发布信息
max字符串作者声明的最高 Zotero 版本,可能带通配符 *(如 8.*)。作者未声明时省略作者发布信息
d日期 YYYY-MM-DD这个安装包的发布日期。没有日期时省略作者发布页

3. 中文引用样式一览 /data/styles.json

收录 CSL 官方样式仓库里默认语言为中文的样式,以及 zotero-chinese/styles 仓库里的 GB/T 7714 系列样式。每一条都是脚本逐个读取样式文件头(<info> 里的标题、ID、类别、许可等)得到的,读不到或缺字段的不收。这份文件只有元数据,本站不搬运、不托管任何样式文件;要安装样式,请按 page 或 file 到来源获取,并遵守 license 写明的许可。

顶层字段
字段类型含义可否为空来源
schema整数格式版本号,目前是 1。不会缺省固定值
checkedAt日期 YYYY-MM-DD最近一次从来源仓库逐个读取样式文件头、核对这份一览的日期。不会缺省生成脚本
site字符串本站地址。不会缺省固定值
note字符串使用说明:只含元数据,不含样式文件。不会缺省固定值
sources数组来源仓库:每项是 { key, label, repo, site, styleCount },styleCount 是核对当天该来源的样式总数(官方取 Zotero 样式库公开索引的条数,社区仓库取样式目录数)。不会缺省来源仓库
count整数styles 的条数。不会缺省生成脚本
styles数组样式元数据,官方在前、社区在后,各自按国标版本从新到旧。不会缺省见下表
styles 数组里每一项
字段类型含义可否为空来源
id字符串样式 ID,即样式文件 <id> 的原文。Zotero 用它区分样式。不会缺省样式文件头
title字符串样式标题,即 <title> 的原文。不会缺省样式文件头
titleShort字符串简称,即 <title-short> 的原文。文件里没有时省略样式文件头
source字符串来自哪个仓库:csl(CSL 官方样式仓库)或 zotero-chinese。不会缺省生成脚本
use字符串适用场景。标题含 GB/T 7714 的写「国家标准 GB/T 7714—年份」;其余按标题、摘要与文档链接写明用途。不会缺省样式文件头
standard字符串对应的国标版本,如「GB/T 7714—2015」。不是国标样式时省略样式标题
citationFormat字符串引文方式,即 <category citation-format> 的值:numeric(数字编号)、author-date(著者-出版年)、note(注释)等。不会缺省样式文件头
fields字符串数组学科类别,即 <category field> 的值,如 generic-base、law。可能是空数组样式文件头
defaultLocale字符串样式的默认语言,如 zh-CN。不会缺省样式文件头
updated日期时间样式文件自己记录的更新时间(<updated>)。不会缺省样式文件头
license对象样式文件自带的许可:url 是 <rights license> 的地址,text 是 <rights> 的原文。不会缺省样式文件头
page字符串(https 地址)样式的介绍网页:官方样式指向 Zotero 样式库里该样式的检索结果,社区样式指向其样式详情页。不会缺省来源网站
file字符串(https 地址)样式文件在来源仓库里的位置,用来核对本条元数据。不会缺省来源仓库
documentation字符串数组样式文件头里 rel="documentation" 的链接,通常是期刊须知或标准原文。文件里没有时省略样式文件头
template字符串样式文件头里 rel="template" 的链接:这个样式是以哪个样式为模板改出来的。文件里没有时省略样式文件头

4. 示例请求

命令行(curl + jq):

# 下载目录源并查看插件数量与生成日期(需要 jq)
curl -s https://zoterocn.org/data/catalog.json | jq '{generatedAt, count}'

# 列出声明适配 Zotero 10 的插件 id
curl -s https://zoterocn.org/data/catalog.json \
  | jq -r '.plugins[] | select(.zotero.majors | index(10)) | .id'

# 引用样式一览:列出全部国标样式的 ID 与标题
curl -s https://zoterocn.org/data/styles.json \
  | jq -r '.styles[] | select(.standard) | "\(.id)\t\(.title)"'

JavaScript(fetch):

// Node.js 18 及以上(自带 fetch),保存为 .mjs 后运行
const res = await fetch("https://zoterocn.org/data/catalog.json");
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const feed = await res.json();
if (feed.schema !== 1) throw new Error("不认识的格式版本");

// 每个插件在 Zotero 10 上能装的安装包(没有就跳过)
for (const p of feed.plugins) {
  const r = p.releases.find((x) => x.t === 10);
  if (r) console.log(p.id, r.v, r.u);
}

截至本页核对时,服务器没有为这些文件开放浏览器跨域读取(响应里没有 Access-Control-Allow-Origin),所以上面的代码适合在 Node.js、脚本或你自己的服务器上运行;别的网站的网页里直接用 fetch 读取会被浏览器拦下。文件一天通常只变一次,建议缓存在自己那边,不必频繁重复下载。

5. 兼容承诺

  • 每份文件顶层都有 schema,目前都是 1。同一个 schema 下字段只增不改:已有字段的名称、类型与含义不变,不会删除;新增的字段可能出现在任何一层。
  • 读取时请先检查 schema,并忽略自己不认识的字段。表里写着「省略」的字段可能整个不存在,请按可选处理。
  • 确需改变已有字段时会换用新的 schema 号,不在原号下悄悄改动。
  • 数组的顺序按上文写明的规则排列,但不要依赖某一项的位置,请用 id 定位。

6. 再利用与署名

  • 插件目录:收录规则写明,目录数据欢迎自由引用,请注明来源。
  • 目录的初始收录名单与中文摘要整理自 zotero-chinese/zotero-plugins 项目的公开插件目录(MIT 协议),安装包的插件标识也主要取自该目录;星标、版本、发布日期与下载数来自各项目在 GitHub 上的公开页面。署名与许可证全文见第三方声明。
  • 引用样式一览:每条元数据摘自样式文件自己的文件头,样式文件本身的许可以 license 字段和来源仓库的说明为准。
  • 仓库里的社区插件代码采用 MIT 许可证,但该授权不自动覆盖整个站点仓库;复用站点其他内容前请先确认相应授权,见项目说明。
  • 数据可能有遗漏或滞后,以各项目主页和来源仓库为准;发现错误欢迎在公开仓库的 Issue 里指出。
